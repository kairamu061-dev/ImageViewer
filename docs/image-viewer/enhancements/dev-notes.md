# enhancements 開発メモ

## 実装上の判断

| 判断内容 | 理由 |
|----------|------|
| トグルボタンをスプリッター外に配置 | スプリッターが幅0になってもボタンは常時表示される必要があるため |
| `setSizes()` 後に `_update_toggle_btn` を明示的に呼ぶ | `setSizes()` は `splitterMoved` シグナルを発火しないため、ボタンテキストが更新されなかった |
| スワップ設定をグローバルにする | タブごとに異なる設定は管理が複雑で、ユーザーにとっても混乱しやすいため |
| `_zoom_pixmap` キャッシュを追加 | ドラッグ中はスケールが変わらないため、毎フレームの `pixmap.scaled()` をゼロコストにできる |
| 自然順ソートを `_natural_sort_key` として共通化し、ファイル一覧と兄弟フォルダ一覧の両方に適用 | 片方だけ直すと「一覧の画像順」と「次フォルダへの移動順」がまた食い違うため |
| `_natural_sort_key` の実装を自前の正規表現ベースから `QCollator`（数値モード・大文字小文字無視）に変更 | `QFileSystemModel`（フォルダツリー）が内部でまさにこの設定の `QCollator` を比較に使っているため。これに合わせることで、数字部分だけでなく非ASCII文字（日本語など）を含む名前もツリー表示順と完全に一致する |

## 発生した問題と対処

| 問題 | 対処 |
|------|------|
| ホイール移動モードで上スクロールが next になっていた | `delta > 0` = 前の画像に修正 |
| フォルダパネル折りたたみ後もボタンが `<` のまま | `_toggle_folder_panel` 内で `_update_toggle_btn` を明示呼び出しに修正 |
| ズーム中に画像が画面外まで飛ぶ | `_clamp_offset` を追加しドラッグ・ズーム後に適用 |
| ファイル名が `1,2,3,11,12,13,21,22,23` のようなフォルダで、送り順が `1,11,12,13,2,21,...` になる（ユーザ報告） | `load_folder()` が `p.name.lower()` の単純文字列ソートだったため。`_natural_sort_key` に差し替えて数値部分を数値として比較するよう修正 |
| 末尾画像から次へ進んだ際の移動先フォルダが、フォルダツリー上の表示順と一致しないことがある（ユーザ報告） | `_get_sibling_folder()` も同じ単純文字列ソートだった一方、フォルダツリー（`folder_tree.py` の `QFileSystemModel`）は数字を数値として扱う自然順ソートを内部で行っており、両者の並び順がズレていたのが原因。`_get_sibling_folder()` にも `_natural_sort_key` を適用し、ツリー表示順と一致させた |
| 上記修正後も、日本語名フォルダ（例: `(C`, `(成`, `(同` で始まる3フォルダ）で移動順がツリー表示順と食い違う（ユーザ報告・再現）| 自前実装の `_natural_sort_key` は Python の素朴な文字列比較（Unicodeコードポイント順）だったため、`同`(U+540C) が `成`(U+6210) より前に来てしまっていた。実際のツリー表示は「成（せい）」→「同（どう）」の五十音読み順。これは `QFileSystemModel` が比較に `QCollator`（ロケール依存・読みを考慮した照合）を使っているためで、コードポイント比較では原理的に再現できない。`_natural_sort_key` を `QCollator`（`setNumericMode(True)` + `CaseInsensitive`、デフォルトロケール）を使う実装に差し替え、`QFileSystemModel` 内部の比較設定と一致させて解決 |
| 隠しフォルダが兄弟フォルダ移動の対象に含まれてしまう（自然順ソート修正時に判明、ユーザ要望で対応） | `_get_sibling_folder()` が `is_dir()` のみでフィルタしており隠しフォルダも対象にしていた。画像ビューアーで隠しフォルダを見に行くことはない前提のため、`QFileInfo(str(p)).isHidden()` で除外。フォルダツリー（`QFileSystemModel`）も同じ判定基準で隠しフォルダを表示しないため、これで両者が完全に一致する |
