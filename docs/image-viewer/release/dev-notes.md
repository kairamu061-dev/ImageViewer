# release 開発メモ

## 実装上の判断

| 判断内容 | 理由 |
|----------|------|
| インストーラーは `--onedir` をラップ（`--onefile` を使わない） | onefile は毎回tempへ展開して起動が遅く、AV誤検知も多い。インストーラーで配るならフォルダ構成でも問題なく、起動の速さを優先 |
| ユーザー単位インストール（`PrivilegesRequired=lowest`） | 管理者権限/UACを避け導入を簡単に。関連付けも HKCU（HKA）で完結し権限不要 |
| 既定アプリへの強制設定はしない | Windows 10/11 はインストーラーからの既定ハンドラ強制変更を許可していない。`OpenWithProgids` で「プログラムから開く」候補に加えるのが現実的な上限 |
| 関連付けを既定オフのタスクに | 勝手に拡張子へ割り込むと利用者が驚くため、明示的に選んだときだけ有効化 |
| 引数起動時は前回セッションを保存しない | ファイルをダブルクリックした単発起動で、保存済みのタブ構成を上書きしないため。`closeEvent` を `_persist_on_close` で分岐 |
| 初期画像の特定を `name` 一致で行う | `%1` の絶対パスと `folder.iterdir()` のパス表記差で `list.index()` が外すのを避けるため、ファイル名で突き合わせる |
| バージョンを `installer.iss` の `#define MyAppVersion` 一箇所に集約 | コード側に version 定義が無いため、リリース番号の単一の出所をインストーラー定義に置いた。初版 1.0.0 |

## 発生した問題と対処

| 問題 | 対処 |
|------|------|
| 現状アプリが起動時引数を無視しており、関連付けを登録しても「ダブルクリックで開く」が機能しない | `main.py`→`MainWindow`→`app_tabs`→`tab_content`→`image_viewer_panel.load_folder` に初期画像パスを伝播する経路を追加して対応 |
| この開発環境に Windows/Python/PyInstaller/Inno Setup が無く、ビルド・動作確認ができない | リポジトリにはスクリプト（`installer.iss`/`build-installer.bat`）のみを用意し、ビルドと確認はユーザーの Windows で実施してもらう（tasks.md の未チェック項目） |
| 初版の `build-installer.bat` が ISCC を既定パス1箇所だけ見ており「見つからない」でビルド失敗（ユーザ実機） | ISCC の探索を複数の既定インストール先（Program Files (x86)/Program Files の Inno Setup 6・5、`%LocalAppData%\Programs`）＋ PATH 上の `where ISCC` に拡張。`%ProgramFiles(x86)%` は `(x86)` の `)` が for ブロックを壊すため、先に変数へ退避してから使う。見つからない場合は探索先と、手動でパス指定する方法を案内するよう改善 |
