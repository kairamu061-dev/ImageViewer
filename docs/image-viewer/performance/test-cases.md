# performance テストケース

## ユニットテスト

| ID | テスト名 | 入力 / 条件 | 期待結果 | ステータス |
|----|---------|------------|---------|-----------|
| U-01 | ImageCache LRU上限 | CACHE_LIMIT(60) を超える件数のインデックスを順に `get_sync`/`_store` する | キャッシュ件数が CACHE_LIMIT を超えず、最も古いアクセスのエントリから破棄される | [ ] |
| U-02 | ImageCache move_to_end | 一度キャッシュした画像を再度 `get`/`get_sync` する | 直近アクセスしたインデックスが破棄順の末尾（最も破棄されにくい位置）に移動する | [ ] |
| U-03 | 一覧表示の可視範囲計算 | スクロール位置・ウィンドウサイズを変えて `_visible_range()` を呼ぶ | 実際に表示されている先頭/末尾インデックスが返る | [ ] |

## インテグレーションテスト

| ID | テスト名 | 前提条件 | 手順 | 期待結果 | ステータス |
|----|---------|---------|------|---------|-----------|
| I-01 | 一覧表示の段階的読み込み | 数百枚規模のフォルダで一覧表示を開く | 開いた直後の状態を観察 | 画面外の画像の読み込みは即座に開始されず、スクロールするにつれて追加で読み込まれる | [ ] |
| I-02 | フォルダツリーの専用プール | フォルダツリーで多数のサブフォルダを持つノードを展開しながら、同時に1枚表示でページ送りする | 両操作を交互に行う | フォルダ展開中も画像のページ送りが極端に遅延しない | [ ] |

## E2Eテスト

| ID | テスト名 | 前提条件 | 手順 | 期待結果 | ステータス |
|----|---------|---------|------|---------|-----------|
| E-01 | 大きいフォルダでの「画像がありません」再発確認 | 画像ファイルが多いフォルダ（不具合が報告された環境に近いもの） | フォルダ内を先頭から末尾まで1枚表示で通して閲覧する | 「画像がありません」が表示されない | [!] |
| E-02 | フォルダツリーの操作感 | 多数のサブフォルダを含むフォルダツリー | フォルダを多数展開・スクロールする | 重さを感じない | [ ] |
| E-03 | 一覧表示のスクロール操作感 | 画像ファイルが多いフォルダ | 一覧表示で最上部から最下部までスクロールする | 重さを感じない | [ ] |
| E-04 | ログによる原因特定 | 「画像がありません」が再発した状況 | `%TEMP%\ImageViewer.log` を確認する | 失敗したファイルパスとQtのエラー内容（またはPython例外）が記録されている | [ ] |

## 実施記録

- 2026-10-10: ユーザ実機確認。E-01（「画像がありません」再発確認）は不合格 — LRU化・リトライ後も再発。原因未解決のため `_load_qimage`/`_load_thumb`/`show_image` にログ出力を追加（E-04）。再発時のログ内容待ち
