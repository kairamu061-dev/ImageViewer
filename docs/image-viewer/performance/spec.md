# performance 仕様

## 機能一覧

| # | 機能名 | 説明 |
|---|--------|------|
| 1 | ImageCache のLRU上限 | 1枚表示用キャッシュを最大件数で制限し、超えたら最も使われていないものから破棄 |
| 2 | 読み込み失敗時のリトライ | `get_sync` で画像デコードが失敗したら即座にもう1回だけ再試行する |
| 3 | フォルダツリー専用スレッドプール | サブフォルダ存在チェックを専用の小さいプールで実行し、画像デコードと競合しないようにする |
| 4 | 一覧表示の可視範囲優先読み込み | サムネイル読み込みを「表示中の行＋前後バッファ」に限定し、スクロールに応じて追加読み込み |
| 5 | 一覧表示専用スレッドプール | サムネイル読み込みを専用プールで実行し、1枚表示のプリロードと競合しないようにする |
| 6 | 診断用ログ出力 | デコード失敗時にQtのエラー内容・例外を `%TEMP%\ImageViewer.log` に記録する |
| 7 | 1枚表示の遅延バックオフリトライ | デコード失敗時、300ms/1000ms/3000msと間隔を空けて最大3回まで自動的に再表示を試みる |

## 各機能の詳細

### ImageCache のLRU上限
- `ImageCache._cache` を `dict` から `collections.OrderedDict` に変更
- 上限 `CACHE_LIMIT = 60`。挿入時に上限を超えたら `popitem(last=False)` で最も古い（最も使われていない）エントリから破棄
- `get()` / `get_sync()` でキャッシュヒット時は `move_to_end()` し、直近アクセスしたものが破棄されにくくする

### 読み込み失敗時のリトライ
- `get_sync()` で `_load_qimage()` が `None` を返した場合、即座にもう1回だけ再試行する
- アンチウイルスやクラウド同期によるファイルの一時ロックなど、一過性のI/O失敗を想定した対策

### フォルダツリー専用スレッドプール
- `FolderOnlyModel._pool` を `QThreadPool.globalInstance()` から専用の `QThreadPool()`（`setMaxThreadCount(2)`）に変更
- 多数のフォルダを展開・スクロールしても、1枚表示や一覧表示のデコード処理を妨げない

### 一覧表示の可視範囲優先読み込み
- `ThumbnailGridView._ensure_visible_loaded()` が現在のビューポートに表示されている行範囲（`indexAt()` で算出）の前後 `COLUMNS × PRELOAD_ROWS`（= 5×2 = 10件）を読み込み対象とする
- 読み込み済み・読み込み指示済みのインデックスは `_dispatched` セットで管理し、重複ディスパッチしない
- `set_images()` / `showEvent()` / `resizeEvent()` / `scrollContentsBy()` の各タイミングで呼び出し、スクロールするたびに新しく見えてきた範囲を追加で読み込む

### 一覧表示専用スレッドプール
- `ThumbnailGridView._pool` を `QThreadPool.globalInstance()` から専用の `QThreadPool()` に変更

### 診断用ログ出力
- `main.py` の `_setup_logging()` で `logging.basicConfig` をファイル出力に設定（`%TEMP%\ImageViewer.log`）。ウィンドウアプリ（`console=False`）でコンソールが無いため
- `_load_qimage` / `_load_thumb` はデコード失敗時に `QImageReader.errorString()` を、例外発生時はスタックトレースをログに記録する（従来は無言で `None` を返すのみだった）

### 1枚表示の遅延バックオフリトライ
- `ImageViewerPanel.show_image()` で `get_sync()` が `None` を返した場合、`_schedule_retry()` で 300ms後に再試行をスケジュールする
- 失敗したら 1000ms後、さらに失敗したら 3000ms後と間隔を空けて最大3回まで再試行する（`_RETRY_DELAYS_MS`）
- 再試行時、ユーザーが別の画像/フォルダに移動していたら何もしない（表示中のフォルダ・インデックスが一致する場合のみ反映）
- 再試行が成功したら、ユーザーの操作なしに自動的に正しい画像に更新される

## エラーケース

| 条件 | メッセージ / 挙動 |
|------|------------------|
| 全てのリトライ（即時1回＋遅延3回）後も画像デコードに失敗する | 「画像がありません」を表示したままになる（恒久的な破損ファイル等を想定） |
| 遅延リトライ待ち中にユーザーが別の画像/フォルダに移動する | リトライ結果は無視され、現在表示中の画像には影響しない |
| LRU上限により現在表示中の画像がキャッシュから外れる | 再表示時に `get_sync()` が同期的に再デコードするのみで、ユーザーには見えない |

## 未対応ケース

- サムネイルのディスク永続化キャッシュ
- フォルダツリーの行描画自体の仮想化・遅延生成
- 読み込み中であることを示すプログレスインジケーター
